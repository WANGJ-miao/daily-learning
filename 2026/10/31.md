## tar bomb

a tar bomb is a common problem when extracting compresed archives on linux.

imagine you download an archive called project.tar.gz.

you expect it to contain a single directory

but what if the archive displays all the files on the surface instead? then after you extract it, all the files are directly dumped into your current directory

how to protect yourself?

### method 1: inspect the archive first

before extracing:

```
tar -tzf archive.tar.gz
```

where -t means list rather than extract

### method 2: always extract into a separate directory

```
mkdir -p /tmp/fzf/extract

tar -xzf fzf-linux.tar.gz -c /tmp/fzf-extract
```

where -c means change directory before extracting

then you can inspect the extracted files before moving the them

```
ls -la /tmp/fzf-extract

mv /tmp/fzf-extract/fzf ..
```

finally remove the temp files

# control my output monitor

there're three important concepts to understand relating to x11 multi monitors

## physical monitor and output

| output name | correspounding device | original resolution | physical size |
|-------------|-----------------------|---------------------|---------------|
| edp-1       | thinkpad screen       | 3072x1920           | 312x195mm     |
| hdmi-1      | external monitor      | 1920x1080           | 598x336mm     |

## framebuffer (the most important concept)

in x11, i can imagine that all the monitors are laid out on a giant 2d canvas.

each monitor accouts for a rectangular area on the canvas.

a rectangular can be described by 4 parmeters: (x, y, width, height), for example:

```
hdmi-1: (0, 0, 2880, 1620)
edp-1 : (0, 1620, 3072, 1920)
```

## physical resolution and logical size

suppose i scale the screen

``` bash
xrandr --output hdmi-1 --scale 1.5x1.5
```

the original resolution is 1920x1080, after scaling, the size becomes 2880x1620

the original output signal is still 1920x1080, but in x11 desktop layout, the logical size becomes 2880x1620, and this is why `--scale` can cause blur

## cheat sheet of `xrandr`

### look for the monitor's info

| command               | usage                                                        |
|-----------------------|--------------------------------------------------------------|
| xrandr                | check all the monitor and available mode                     |
| xrandr --query        | check current's status, position, and resolution             |
| xrandr --listmonitors | check the layout of monitors                                 |
| xrandr --verbose      | check the detailed info, including the transfromation matirx |

### resolution and refresh rate

| command                                | usage                         |
|----------------------------------------|-------------------------------|
| xrandr --output edp-1 --mode 3072x1920 | set the resolution            |
| xrandr --output edp-1 --rate 120       | set the refresh rate          |
| xrandr --output edp-1 --auto           | choose the mode auotmatically |

### position of monitor

| command          | usage                                    |
|------------------|------------------------------------------|
| --above edp-1    | put above edp-1                          |
| --below edp-1    | put below edp-1                          |
| --left-of edp-1  | put to the left of edp-1                 |
| --right-of edp-1 | put to the right of edp-1                |
| --pos 0x0        | set the coordinate of the left up corner |
| --primary        | set the primary monitor                  |

### scale

| command           | usage                                                                 |
|-------------------|-----------------------------------------------------------------------|
| --scale 1x1       | restore to the original size                                          |
| --scale 1.25x1.25 | scale the logical size to 1.25 times(zoom out to 80% of original size |

### open/close monitor

``` bash
# close
xrandr --output hdmi-1 --off

# restart, however, --auto will automatically choose the mode, maybe not the mode you want
xrandr --output hdmi-1 --auto
```

# WirePlumber

Wire: 线缆， 连接
Plumber： 管道工， 水管工

Just think it as a manager of the audio pipeline

in Linux, WirePlumber is Session Manager of PipeWire, who is responsible for:
1. manage the audio device, like microphone, speaker
2. decide which device is the audio stream connected to
3. manage device switching and audio routing
4. handle the audio devices' strategy and status

A simple comprehension:

PipeWire : accounts for the tranfering and handling of the audio-visual data stream

WirePlumber: accounts for how should these data streams be connected and used

pw-top : top for the PipeWire audio graph. While top monitors cpu processes, pw-top monitors audio/video processing nodes and thier real-time scheduling.
