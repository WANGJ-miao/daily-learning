# Linux Graphic Desktop

在x11中, 显示服务器和窗口管理器通常是不同的进程

在wayland中, 合成器同时承担显示服务器和窗口管理的职责

## x11

X Window System第11版协议

图形应用与负责显示的服务器是两个不同的进程, 甚至可以运行在不同的电脑上

例如emacs是一个图形应用, 但是不直接决定最终出现在窗口的什么位置, 而是通过x11与显示服务器交互

典型的x11桌面包括:

1. X Server: like X org, 处理窗口, 显示, 和输入相关的请求
2. Window Manager: like i3, 管理窗口的位置, 尺寸, 布局
3. Compositor: like picom, 负责透明, 阴影, 合成... 有些window manager自带合成的功能
4. Application: like emacs, firefox
5. toolkit: like gtk, qt, help the application to draw the button, menu...

# from input to to X

[https://wayland-book.com/introduction](https://wayland-book.com/introduction)

The kernel gets an event from an input device.

The X server determines which window the event affects and sends it to the clients that have selected for the event in question on that window. (select for : 请求接受, 订阅)

The display resources are shared between all of my applicaions, and the role of the wayland compositor is to dispatch input events to the appropriate wayland client and to display their windows in their appropriate place on my outputs. The process of bringing together all of my application windows for display on an output is called **compositing** -- and thus we call the software which does this the *compositor*.
