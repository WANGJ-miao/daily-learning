# 电力电子
- [X] 研究不同的滤波电容处理不同的电压纹波?
  电容可以模型化为
  ESL-----ESR------ideal capacity
  低频的时候, 电容特性主导, 频率越高阻抗越低
  达到自谐振频率时, 电容和寄生电感抵消, 阻抗最低
  再提高频率, ESL开始主导, 表现得越来越像电感
  | 电容           | 主要用途                 | 特点                   |
  |----------------|--------------------------|------------------------|
  | 100～220µF电解 | 低频波动、插拔、负载突变 | 储能多，但ESR、ESL较大 |
  | 10～22µF陶瓷   | 开关频率及其附近         | ESR、ESL较小           |
  | 1µF陶瓷        | 更高频的谐波             | 高频性能较好           |
  | 100nF陶瓷      | 很快的开关边沿和尖峰     | 小、寄生电感低         |
- [X] 陶瓷电容紧贴半桥Q1/Q2, 使得高频回路最小, 这是什么原因
  - 缩短快速电流路径。
  - 减小回路包围面积。
  - 减小寄生电感。
  - 降低MOSFET上的电压尖峰和振铃。
  - 减少电磁辐射。
  - 避免干扰ADC、STM32和栅极驱动。
  一般会把更小的电容放的更近
- [X] 电解电容和陶瓷电容的区别? 各自有什么特点? 怎么放置?
  电解电容
  优点：
  - 单颗容量大。
  - 单位容量成本低。
  - 比较适合几十到几百微法。
  - 适合低频储能、输入线扰动和负载突变。
  - 一定的ESR有时还能给LC系统增加阻尼。
  缺点：
  - 有极性，接反可能损坏甚至爆裂。
  - ESR和ESL通常比陶瓷电容大。
  - 高频性能较差。
  - 纹波电流会使它发热。
  - 寿命受温度影响明显。
  - 容量公差通常较大。
  电解电容
  优点：
  - 单颗容量大。
  - 单位容量成本低。
  - 比较适合几十到几百微法。
  - 适合低频储能、输入线扰动和负载突变。
  - 一定的ESR有时还能给LC系统增加阻尼。
  缺点：
  - 有极性，接反可能损坏甚至爆裂。
  - ESR和ESL通常比陶瓷电容大。
  - 高频性能较差。
  - 纹波电流会使它发热。
  - 寿命受温度影响明显。
  - 容量公差通常较大。
a trick:
一个大电容用两个小电容替代, 总容量不变, 同时ESR减半, ESL减小, 
纹波电流由两颗分担, 热量由两颗分担, pcb上可以分别靠近功率器件放置

** 我发现几个道理 **
1. 电力电子设计追求的不是把性能达到多机制, 而是结果可控, 稳定
2. 所有元件的选择都是有两面性的, 没有越怎么样越好
例如大电容可以帮助负载瞬态和低频储能
但是也要付出一定的代价:'
1. 上电时浪涌电流变大
2. 软启动时间增加
3. 过流保护更容易在启动时触发
4. pcb面积和成本增加
5. 会改变控制环的极点, 需要重新设计pi参数

# FREERTOS
a thread of execution is called a task
the interrupt handlers can be kept very short by deferring processing to tasks
freertos supports approximately twenty different compilers and forty processors
freertos port: a supported combination of compiler and processor
out of box 开箱即用
each demo application built 'out of the box' with no compiler errors or warnings
这里built是不及物动词, 表示compiled, 就是每一个demo程序都能开箱即用成功编译
TCB : Task Control Block
FreeRtosconfig.h tailors FreeRTOS for a specific application, so it should be located in a directory that is part of the application, not in a directory that contains the FreeRTOS source code
tasks.c and list.c implement the core Freertos kernel functionality and are always required!!!
`queue.c` provides both queue and semaphore services.
`timer.c` provides software timer functionality
`event_groups.c` provides event group functionality
`stream_buffer.c` provides both buffer and message buffer functionality
`sroutin.c` implement the FreeRTOs co-routine functionality. (No longer maintained)
_coroutine: a execution unit lighter than thread, used to be used on very small microcontrollers, which are rarely used now_
It seems that heap allocation scheme needs to be manually included~ in FreeRTOS/Source/portable/MemMang
freertos requires the inclusion of three directories in the compiler's include path:
1. path to the core FreeRTOS kernel header files, FreeRTOS/Source/include
2. The path to the source files specific to the FreeRTOS port in use, FreeRTOS/Source/portable/\[*compiler*\]/\[*architecture*\]
3. the path to the correct FreeRTOSConfig.h header file
