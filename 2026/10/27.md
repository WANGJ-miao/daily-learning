## decorator

### dataclass

It makes class that only carries data in python easier to write. Just like a simple struct in c. It generates common methods for a class, such as `__init__()` and `__repr__()`[^1] For example:

``` python
@dataclass
class PointState:
	position : np.ndarray
	velocity : np.ndarray
	accleration : np.ndarray
```

Instead of:

``` python
class PointState:
    def __init__(self, position, velocity, acceleration):
        self.position = position
        self.velocity = velocity
        self.acceleration = acceleration
```

[^1]: repr means representation, showing a readble representation for programmers

## WHAT IS A DECORATOR?

a decorator receives a object and modifies or repalce it. Kinda like the concept of metaprogramming in lisp.

`@decorator + something` is basically `decorator(something)`

For example:

``` python
@log_call
def add(a, b):
	return a + b
```
	
->

``` python
def add(a, b):
	return a + b

add = log_call(add) # change the reference of add from add(original) to log_call(add)
```

a simple decorator may look like this (it's basically a function):

``` python
def log_call(func):
	def wrapper(*args, **kwargs):
		log(
  * )
		return func(*args, **kwargs)
	return wrapper

```

However, the wrapper needs to know the metadata of the original function func, which is "add" here. So we use another wrapper inside log_call to succeed from "func".

so we change the code to the following:

``` python
from functools import wraps

def log_call(func):
	@wraps(func) # decorator "wraps" records the metadata like name, docs, wrapped...
	def wrapper(*args, **kwargs):
		log()
		return func(*args, **kwargs)
	return wrapper
```

some useful decorators:

| decorators    | usage                                              |
|:--------------|:---------------------------------------------------|
| @property     | change method into a attribute                     |
| @staticmethod |                                                    |
| @classmethod  |                                                    |
| @cache        | automatically cache the history caculation results |

### @classmethod is often used to write alternative class constructor

``` python
class Robot:
	def __init__(self, name):
		self.name = name
		
	@ classmethod
	def from_config(cls, config):
		return cls(config["name"])
```

difference between clasmethod and staticmethod : classmethod accepts cls(the class) as the first augument("cls" has no specific meaning, it's just a conventional name) and staticmethod accepts no argument.

staticmethod is often used to return class variable. staticmethod cancels the default behaviour of automatically binding self when access an instance.

above are function decorator, and class decorator is alike

## spice directive system

| directive | usage                                                     |
|:----------|:----------------------------------------------------------|
| .param    | define parameters, variables and expressions              |
| .step     | scan the parameters, or repeatedly execute the simulation |
| .meas     | automatically measure the outcome of simulation           |
| .func     | define our own math function                              |
| .tran     | transient simulation                                      |
| .ac       | AC small signal analysis                                  |
| .dc       | DC scan                                                   |
| .op       | solve for the dc operating point                          |
| .include  | include external model or directive                       |
| .model    | define the component model                                |
| .subckt   | define the reusable subcircuit                            |
| .save     | only save the necessary data                              |

### .param

define variable and expressions, for example

``` spice
.param VIN=12
.param RLOAD=10
```

then in the scheme, write the value of each components as:

``` spice
Vin: {VIN}
Rload: {RLOAD}
```

### use math expression in param

ltspice supports some common math operations

``` spice
.param A=10
.param B=2*A+5
.param C=sqrt(A*A+B*B)
.param D=if(A>5, 100, 200)
```

for example, for a ideal CCM Buck:

.parma VIM=12
.param DUTY=0.4
.param VOUT_IDEAL=VIN*DUTY

### .step

Automatically execute simulation for multiple times.

#### specify several discrete values

``` spice
.param LVAL=100u
```

set value of L1 to {LVAL}

and then add

``` spice
.step parma LVAL list 47u 1007 200u
```

then ltspice will automatically execute simulation for three times

#### specify the scanning range and the stride

``` spice
.step param LVAL 20u 250u 50u
```

GRAMMA

``` spice
.step param parameter-name start end stride
```

also scan in logarithmic sweep 

``` spice
.step dec param LLOAD 10u 1 5
```

It means sweep from 10u to 1m and 5 sampling points every decade

#### sweep multiple parameters at the same time

``` spice
.step param lval list 47u 100u 220u
.step param fsw list 50k 100k 200k
```

then ltspice will simulate `3 * 3 = 9` times, which is called nested sweep

#### only sweep the specified parameter group

use table function

``` spice
.step param N list 1 2 3

.param lval=table(N, 1,47u, 2,100u, 3,220u)
.param fsw=table(N, 1,200k, 2,100k, 3,50k)
```
In this way, ltspice will only simulate for 3 times, instead of 9 times

### .meas

let ltspice automatically analyze the outcome of simulation

Basic gramma

``` spice
.meas TRAN <name> <operation> <expression> FROM <start> TO <end>
```

for example:

``` spice
.meas TRAN VAVG AVG V(out) FROM 8m to 10m
```

- .meas			: the directive
- .tran			: measure the outcome of transient simulation
- VAVG			: the name for this measurement
- AVG				: calculate the average
- V(out)			: measure the voltage of the out node
- FROM 8m TO 10m	: only analyze data from 8m to 10m

some useful measuring operator:

- avg
- max
- min
- pp : peak to peak
- rms
- integ : integration
- find : find value at specific time or under specific condition
- when : find the time under certain condition

C-L : open spice error log to check the outcome of your measurement

### a usage

find the best param in a range of values

``` spice
; Circuit parameters
.param VIN=12
.param FSW=100k
.param DUTY=0.4
.param LVAL=100u
.param RLOAD=10

; Derived parameters
.param TPER=1/FSW
.param TON=DUTY*TPER

; Parameter sweep
.step param LVAL list 47u 68u 100u 150u 220u

; Transient simulation
.tran 0 10m 0 100n

; Measurements
.meas TRAN Vavg AVG V(out) FROM 8m TO 10m
.meas TRAN Vripple PP V(out) FROM 8m TO 10m
.meas TRAN Ipeak MAX I(L1) FROM 8m TO 10m
.meas TRAN Iripple PP I(L1) FROM 8m TO 10m

; Derived measurement
.meas TRAN RipplePct PARAM 100*Vripple/Vavg
```

### .func

define my own function, for example:

``` spice
.func parallel(a,b) {a*b/(a+b)}

.param req=parallel(100,200)
```

or write the theoretical buck inductor current ripple into function, as:

``` spice
.func dIL(vin,d,f,L) {vin*d*(1-d)/(f*L)}
```

use it

``` spice
.param IRIPPLE=dIL(12,0.4,100k,100u)
```
