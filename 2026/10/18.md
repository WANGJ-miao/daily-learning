# Emacs

ordinary-lisp-function after adding (interactive) becomes an interactive command, which means it becomes callable from lisp, callable from M-x, and can be bound to a key.

Most editing command that I use is an interactive command. For example:

``` elisp
(defun my-insert-date()
  "insert current time"
  (interactive)
  (insert (format-time-string "%Y-%m-%d")))
```

# 从我按下j, 到光标实际向下移动一行, 究竟发生了什么?

整个图形系统分为6层:
1. Application
2. GUI Toolkit (GTK, Qt, Win32...)
3. Display Server / Compositor(Xorg, Weston, Mutter, KWin) 决定窗口如何显示, 重叠和接收输入
4. Graphics Stack(图形渲染栈)(Cairo, Mesa, OpenGL, Vulkan, DRM/KMS), 把图形变成像素, 并准备显示
5. GPU / Display Control 
6. Monitro(显示器)

输入链路: 键盘/鼠标 -> 驱动程序 -> 输入系统 -> 图形系统 -> 应用程序

## FrameBuffer 

一块储存像素数据的缓冲区 例如一幅1920 * 1080的图像, 使用4字节储存RGBA, 那就是1920 * 1080 * 4 Byte / Frame

## Display Controller

按照时序读取准备好的像素数据, 通过HDMI, DisplayPort, eDP等显示链路输出到屏幕

Linux中, 操作系统通过DRM/KMS等接口控制这部分显示硬件

DRM(Direct Rendering Manager)

KMS(Kernel Mode Setting)

## 窗口系统

多个程序都想绘制图像, 但他们不能直接修改FrameBuffer, 需要窗口系统(Window System)处理重叠关系

应用程序负责自己的窗口内容, compositor 负责整个桌面
