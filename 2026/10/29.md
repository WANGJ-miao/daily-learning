# emacs

## use-package 

use-package is basically a elisp macor

``` elisp
(use-package PAKCAGE-NAME
	:keyword1 value1
	:keyword2 value2
	...)
```

### some important keywords

- :ensure t -> install or I can write (setq use-package-always-ensure t), so that I won't need to write :ensure t everytime
- :init -> execute before teh package is loaded. often set some variables that is needed to be loaded before the pacakge is loaded in this area
- :config -> execute after the package is loaded
- :costum -> use the emacs customization to set the variables
- :bind -> keybindings

before: (global-set-key (kbd "C-c g") #'magit-status)
now: 

``` elisp
(use-package ...
	:bind
	("C-c g" . magit-status))
```
	
- :hook -> hook functions

``` elisp
(use-package ...
	:hook
	(prog-mode . display-line-numbers-mode))
```

## directories in root dir

/home, /root user's files and config
/usr, /bin, /sbin, /lib : program, command, share library and other resources
/etc : system config file
/var, /tmp, /run :logfile, cache, temp data, and running status
/dev, /proc, /sys: device interface, and virtual file system
/boot, /mnt, /media, /opt, /srv : boot file, mount point, extra software, and service data

## there are many solutions in linux to solve the problem of software versions in a server used by multiple users

1. project scale isolation like venv in python
2. each user install his own program in /home/\<user\>/.local/bin/
3. install different versions in different paths, like /opt/mytool/1.0/ and /opt/mytool/2.0
4. use containers to isolate, like DOCKER
