# c

there're three ways to exit a program:

1. return 0;
2. exit(0);
3. _exit(0);

| 特性                       | `return 0;`（在 main 中） | `exit(0)`    | `_exit(0)`   |
|----------------------------|---------------------------|--------------|--------------|
| 结束整个进程               | ✅                        | ✅           | ✅           |
| 刷新 stdio 缓冲区          | ✅                        | ✅           | ❌           |
| 执行 `atexit()` 注册的函数 | ✅                        | ✅           | ❌           |
| 关闭进程的文件描述符       | ✅                        | ✅           | ✅           |
| 可以在普通函数中调用       | ❌ 不会结束进程           | ✅           | ✅           |
| 所属头文件                 | 无                        | `<stdlib.h>` | `<unistd.h>` |

``` c
# include <stdio.h>
# include <unistd.h>

int main() {
  printf("Hello, world!");

  _exit(0);
}
```

this program doesn't print "hello world", the reason is that _exit(0) suddenly stop the process, without flushing the stdout buffer, and what printf does is basically put the chars into the stdout buffer. ofcource, you can flush the buffer manually

``` c
fflush(stdout);
```

printf -> glibc -> stdout buffer -> write(system call) -> linux kernel -> terminal

_exit 跳过的是用户空间的正常终止处理， 而不是内核对进程资源的回收

# user space and kernel space

user space is the environment in which ordinary applications execute. examples include : my c programs, firefox, emacs, bash, most of the GNU C Library (glibc)

kernel space is where the Linux kernel executes. The kernel is responsible for managing essential system resources. for example:

| component          | responsibility                             |
|--------------------|--------------------------------------------|
| scheduler          | decides which thread runs on a cpu         |
| memory management  | manages virtual memory and page tables     |
| VFS                | provides a common interface for filesystem |
| device drivers     | communicate with hardware                  |
| network stack      | implements TCP/IP and other protocols      |
| process management | create and manage processes                |

the kernel runs with elevated cpu privileges. however, user space and kernel space are not two separate cpus or two separate physical memories.

``` plain_text
On a typical x86-64 Linux system:
- User code executes at Ring 3.
- Kernel code executes at Ring 0.
```

## what is a system call?

system call, often abbreviated assyscall, is a controlled mechanism that allows a user-space program to request a service from the kernel.

for example, suppose my program wants to write a file, which is not an operation that can be performed independently by the ordinary user-space

the kernel must resolve the file's path, check access permissions, locate the corresponding filesystem object, create the necessary kernel bookkepping structures, return a file descriptor to the application

# FILE and fd(file descriptor)

FILE is a type defined by the c standard library. It's a stream object managed by the C standard library.

``` c
int fd = open("hello.txt", O_RDONLY);
FILE *fp = fopen("hello.txt", "r");
```

open versus fopen

a FILE object maintains information such as:

``` c
struct conceptual_FILE {
    int fd;
    
    char *buffer;
    
    size_t buffer_size;
    // ...
}
```

a powerful unix concept: Many different I/O resources can be accessed through the same file descriptor interface

# strace

a powerful tool to trace system calls and signals

``` c
wangj@thinkpad:c$ strace -e trace=write ./printf
write(1, "ABC", 3ABC)                      = 3
write(1, "D", 1D)                        = 1
+++ exited with 0 +++
```

``` c
int main() {
  printf("A");
  printf("B");
  printf("C");

  fflush(stdout);

  write(STDOUT_FILENO, "D", 1);

  return 0;
}
```

write directly invokes the syscall interface in through glibc

monitor multiple system calls:

``` bash
strace -e trace=read,write,openat,close ./hello
```

or filter by category:

``` c
# file-related system calls
strace -e trace=file ./hello

# process-related system calls
strace -e trace=process ./hello

# network-related system calls
strace -e trace=network ./hello

# memory-related system calls
strace -e trace=memory ./hello
```

trace a running process with `-p`

# git

``` bash
git clone <url> --depth=1
```

--depth=1 : 只获取目标分支最近的一层提交历史

``` bash
git fetch --deepen=5
```

加深浅科隆历史， 获得至多五层额外的祖先提交

``` bash
git fetch --unshallow
```

恢复完整历史

``` bash
git clone --filter
```

控制下载哪些git对象， 这个叫部分科隆(partial clone)

``` bash
git clone --filter=blob:none
```

获取需要的提交和目录结构信息， 但不预先下载那些暂时不需要的blob对象, 在checkout的时候， 仍然会下载文件内容， 这样节省历史版本重的文件内容， 而不是当前工作取必需的文件。 This is called Lazy Fetching(按需获取)

``` bash
git clone --filter=blob:limit=1m url
```

初始对象传输的时候， 过滤掉大小至少为1MB的blob

git sparse-checkout 只把指定目录放进工作区

``` bash
git sparse-checkout set firmware/stm32
```

--single-banch : 只跟踪一个远程分支历史
--bare : 创建没有工作取的裸仓库, 可以用来作为git服务器的仓库
--recurse-submodules : 初始化并科隆子模块

# include libraries

when writing c on linux, I'll encounter 3 layers:

| layer                  | meaning                       | example                   |
|------------------------|-------------------------------|---------------------------|
| ISO C standard library | defined in c language         | stdio.h stdlib.h          |
| POSIX API              | interface on unix-like system | unistd.h fcntl.h          |
| Linux specific API     | extended interface on Linux   | sys/epoll.h sys/inotify.h |

c header files

1. stdio.h standard input/output
2. stdlib.h standard library
3. string.h String
4. stdint.h standard integer types(**important in embedded development**)`int8_t uint8_t ...`
5. stddef.h standard definitions (provides some fundamental types and macro: `size_t, ptrdiff_t, NULL, offsetof()`)
6. errno.h error number(provide errno)

posix header files

1. unistd.h unix standard(`read, write, close, fork, execute, getpid, pipe, sleep....`)
2. fcntl.h file control(`open, fcntl`)
3. sys/types.h system types(`pid_t, off_t, ssize_t`)
4. sys/stat.h file status
5. sys/wait.h
6. sys/socket.h

linux

1. signal.h
2. pthread.h
3. dirent.h
4. termios.h
5. poll.h
6. sys/select.h
7. sys/mman.h
