# perf


(performance profiling tool)

comparison of some tools:

1. htop : check the systemc resources occupation. (which process is ocupying the cpu?)
2. strace : trace the system call. (what sytemcall does the program call)
3. gdb : debug the program
4. time : measure the executing time
5. perf : analyze the performance of the program

perf involves 3 layers of things:

1. the tool exposed to users
2. `perf_event_open()` systemcall
3. PMU(Performance Monitoring Unit), which use hardware counters to record the events in cpu

unfortunately, my there isn't a specific software implementation for my kernel.

| 命令          | 功能                   |
|---------------|------------------------|
| `perf stat`   | 统计 CPU 性能事件      |
| `perf record` | 采样并记录程序运行数据 |
| `perf report` | 分析 record 生成的数据 |
| `perf top`    | 实时显示 CPU 性能热点  |
| `perf list`   | 列出支持监测的事件     |

现代 Intel 处理器可能包含不同类型的 CPU 核心

| 核心类型  | 英文                      | 主要特点                           |
|-----------|---------------------------|------------------------------------|
| P-core    | Performance Core          | 高性能，适合计算密集型任务         |
| E-core    | Efficiency Core           | 更注重能效                         |
| LP E-core | Low Power Efficiency Core | 更注重低功耗，通常用于轻量后台任务 |

``` plain_text
# 查看详细性能统计
perf stat -d ./program

# 重复测量五次
perf stat -r 5 ./program

# 记录采样数据
perf record ./program

# 记录函数调用关系
perf record -g ./program

# 查看分析结果
perf report

# 查看汇编指令级别的热点
perf annotate

# 实时监测程序热点
perf top -p PID

# 监测运行中的程序五秒
perf stat -p PID sleep 5
```

# 为什么改不了/proc/sys/kernel/kptr_restrict这个文件？

原因是/proc/中的文件是虚拟文件， 不是一个真实存在的文件， 所以不能直接写然后保存

可以这样写入：

``` bash
echo 0 | sudo tee /proc/sys/kernel/kptr_restrict
```

为什么 vim 会报错？原因是vim在保存的时候还会调用fsync(fd);（请求将文件修改同步到持久存储）

更加正确的方式：

``` bash
sudo sysctl -w kernel.kptr_restrict=0
```
