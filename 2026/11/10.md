# queue

this is a very common concepts in computer science, which follows a FIFO principle(first in first out)

## why need queue?

problem A : race condition. (maybe taskA is writing a data while taskB is reading it. taskB may get a mixture of old and new data)

problem B : missing data. (the data taskA send may be overwritten, if taskB does not read it immediately)

problem C: cpu usage. (if a task continuously check whether a data is avaliable, it will cause busy waiting)


## how does freertos queue work?

sensor task -> xQueueSend() -> **FREERTOS QUEUE(data[0], data[1]...)** -> xQueueReceive() -> control task

freertos queue has the following properties:

1. it srores data
2. it is thread-safe
3. task can block(**Arguably the most important one.** If the queue is empty, the receive task can enter blocked state)

# abi(application binary interface)

api(application programming interface)

ABI 规定：
- 函数参数如何传递。
- 函数返回值放在哪里。
- 哪些寄存器需要由被调用者保存。
- 栈需要按照多少字节对齐。

- 结构体如何布局。

# Cortex-m7 也有Mode和Privilege Level

1. Cortex-M7 有两种处理器模式
ARM Cortex-M7 定义了：
- Thread mode：通常用于执行普通应用代码。
- Handler mode：用于执行异常处理程序。

2. Cortex-M7 另外定义了两个特权级
分别是：
- Privileged（特权级）
- Unprivileged（非特权级）
它们与 Mode 的关系是：
| Mode         | Privileged | Unprivileged |
|--------------|------------|--------------|
| Thread mode  | ✅         | ✅           |
| Handler mode | ✅         | ❌           |


Cortex-M7 通过哪个寄存器管理特权级？

CONTROL寄存器

CONTROL[0] = nPRIV
CONTROL[1] = SPSEL

nPRIV : 控制Tread mode的特权级
SPSEL : 决定使用哪一个栈指针

cortex-M 提供两个栈指针:MSP(main stack pointer) PSP(process stack pointer)

# cortex-M7 上电工作初始流程

向量表重的前两个字分别提供MSP(sp)和Reset Handler(pc)地址

刚上电的的时候的默认初始状态：Thread mode, Privileged, SP=STACK POINTER

使用freertos： xTaskCreate() -> 为每一任务创建栈帧 -> xTaskStartScheduler() -> Thread mode, Using psp

一般来说， 如果就是一个普通的baremetal program, 就只使用msp， 完全没有使用psp的必要

如果使用freertos, freertos中创建的任务会默认使用psp

``` plain_text
thread mode / handler mode

psp         / msp
```

这两个并不一一对应， handler mode 只使用msp， thread mode可以选择使用psp还是msp（由Cortex-M 的 CONTROL 寄存器决定）

## the starting procudure

``` c
static void prvPortStartFirstTask( void )
{
	/* Start the first task.  This also clears the bit that indicates the FPU is
	in use in case the FPU was used before the scheduler was started - which
	would otherwise result in the unnecessary leaving of space in the SVC stack
	for lazy saving of FPU registers. */
	__asm volatile(
					" ldr r0, =0xE000ED08 	\n" /* Use the NVIC offset register to locate the stack. */
					" ldr r0, [r0] 			\n"
					" ldr r0, [r0] 			\n"
					" msr msp, r0			\n" /* Set the msp back to the start of the stack. */
					" mov r0, #0			\n" /* Clear the bit that indicates the FPU is in use, see comment above. */
					" msr control, r0		\n"
					" cpsie i				\n" /* Globally enable interrupts. */
					" cpsie f				\n"
					" dsb					\n"
					" isb					\n"
					" svc 0					\n" /* System call to start first task. */
					" nop					\n"
				);
}
```

``` c
void vPortSVCHandler( void )
{
	__asm volatile (
					"	ldr	r3, pxCurrentTCBConst2		\n" /* Restore the context. */
					"	ldr r1, [r3]					\n" /* Use pxCurrentTCBConst to get the pxCurrentTCB address. */
					"	ldr r0, [r1]					\n" /* The first item in pxCurrentTCB is the task top of stack. */
					"	ldmia r0!, {r4-r11, r14}		\n" /* Pop the registers that are not automatically saved on exception entry and the critical nesting count. */
					"	msr psp, r0						\n" /* Restore the task stack pointer. */
					"	isb								\n"
					"	mov r0, #0 						\n"
					"	msr	basepri, r0					\n"
					"	bx r14							\n"
					"									\n"
					"	.align 4						\n"
					"pxCurrentTCBConst2: .word pxCurrentTCB				\n"
				);
}
```

# uuid(universal unique identifier)

length: 128bits (16bytes), is usually represented in hexadecimal 8-4-4-4-12

80842d2f-6f6f-4143-9508-f4bc822574ee

| 版本    | 生成方式                     | 特点                   |
|---------|------------------------------|------------------------|
| UUID v1 | 时间戳 + 节点标识等          | 可能暴露时间和设备信息 |
| UUID v4 | 随机数                       | 简单，应用广泛         |
| UUID v5 | 命名空间 + 名称的 SHA-1 哈希 | 相同输入生成相同 UUID  |
| UUID v7 | Unix 时间戳 + 随机数据       | 适合数据库排序         |

UUIDs come in different versions. They are all 128 bits long, but each version uses these bits differently

for UUID v4:

``` plain_text
xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx
              ↑    ↑
           version variant
```
