# software management

Linux 的文件系统通常按照文件的用途组织，而不是按照软件的名字组织。

``` bash
/
├── usr/
│   ├── bin/
│   │   └── foo
│   ├── lib/
│   │   └── foo/
│   └── share/
│       └── foo/
│           ├── icons/
│           └── documentation/
├── etc/
│   └── foo/
│       └── foo.conf
└── var/
    ├── lib/
    │   └── foo/
    └── log/
        └── foo.log
```
| 目录         | 用途                       |
|--------------|----------------------------|
| `/usr/bin`   | 普通用户程序的可执行文件   |
| `/usr/lib`   | 库文件、程序内部组件       |
| `/usr/share` | 与 CPU 架构无关的共享数据  |
| `/etc`       | 系统级配置文件             |
| `/var/lib`   | 软件需要长期保存的运行状态 |
| `/var/log`   | 日志                       |

/usr: 由发行版管理的软件
/usr/local : 系统管理员手动安装的软件
/opt : 独立安装的第三方软件， 适合需要保存完整目录结构的软件， 然后再使用软连接链接/opt/myapp/bin/myapp到/usr/local/bin/myapp中
~/.local : 不需要root权限的个人软件

**程序本身、程序的配置、程序产生的数据，最好分开存放。**

| 目录             | 典型用途         |
|------------------|------------------|
| `/etc`           | 系统级配置       |
| `~/.config`      | 用户个人配置     |
| `~/.local/share` | 用户个人应用数据 |
| `~/.local/state` | 用户个人运行状态 |
| `~/.cache`       | 可重新生成的缓存 |
| `/var/lib`       | 系统级应用状态   |
| `/var/log`       | 系统日志         |
| `/tmp`           | 临时文件         |

# linux link

in linux, there are two different basic links: soft link and hard link

hardlink: multiple filenames point to the same inode

softlink: a file saves another file's path, and the file has its own inode

in linux, there're three different concpts: filename, inode(file meta data), datablocks

| 层次                                     | 职责                                               |
|------------------------------------------|----------------------------------------------------|
| `rm`（用户空间程序）                     | 请求删除指定文件名                                 |
| VFS（Virtual File System，虚拟文件系统） | 处理路径解析、权限检查、调用具体文件系统操作       |
| ext4 / XFS / Btrfs                       | 负责具体的目录项修改、inode 生命周期和存储空间回收 |

# curl and wget

## curl(client url)

``` bash
curl -fsSL -o file.zip https://example.com/file.zip
```

very useful

-f: fail on http errors(一般情况下如果404错误， curl仍然会打印信息并且返回值是0 ，代表这个命令成功运行了， 但是-f会让退出码变成非0并且立即退出)
-s: silent
-S: still show the errors
-L: follow redirects

## web(world wide web get)

especially for downloading resources

``` bash
wget http://example.com/file.zip
```

默认就是将文件下载到当前目录

-O file: 指定文件名(different from curl)
-c: 断点续传 (`curl` also support this: `curl -C - -O https://example.com/bigfile.zip`, `-C <offset>`, and `-C -` means to calculate it automatically)

-b: 后台下载
-r: 递归下载 use `-l num` to specify the depth

## CMSIS

cmsis :` Cortex Microcontroller Software Interface Standard `, it's a whole set of standard

| 组成部分    | 作用                                       |
|-------------|--------------------------------------------|
| CMSIS-Core  | Cortex-M 内核寄存器、异常、中断等标准接口  |
| CMSIS-RTOS2 | 实时操作系统的标准 API                     |
| CMSIS-DSP   | 数字信号处理函数库                         |
| CMSIS-NN    | 面向微控制器的神经网络计算函数             |
| CMSIS-DAP   | 调试器与上位机之间的标准通信协议及固件实现 |

`DAP：Debug Access Port`

DAP 是目标芯片内部的调试访问组件。

CMSIS-DAP 是调试软件与调试器之间的一套标准通信协议及参考固件实现。他们不是同一个硬件。

## 为什么不让 PWLINK 自动决定使用 SWD？

同一个调试器可能支持多种调试协议。OpenOCD 负责选择和配置，PWLINK 固件负责执行对应的硬件操作。PWLINK MCU 也是有自主性的， PWLINK 的自主性主要体现在底层通信的执行，而不是自动理解所有目标芯片的烧录需求

我原先认为：

> STM32 内部有地址译码硬件，因此它会把写入操作送到 Flash，Flash 不就把数据存进去了吗？

不是这样。

Flash 的存储单元不能像 SRAM 一样，简单地通过普通写入任意改变内容。

对于常见 NOR Flash：
- 擦除通常以 Sector 或 Page 为单位。
- 编程通常具有规定的写入粒度。
- 已编程的位通常不能直接从 0 恢复到 1，需要先擦除。
- 编程时可能需要设置控制寄存器并等待硬件操作完成。

因此，即使你知道 Flash 地址，也不意味着直接执行一次普通内存写入就能完成烧录。所以openocd需要flash driver

在通过 SWD 访问 STM32 内部存储器时，相关的总线互连和地址译码硬件仍然参与工作。

关键区别在于：访问请求不一定来自 CPU。

一个很有趣的做法方法手法：OpenOCD 可以通过调试器把一小段程序上传到 STM32 的 RAM，再控制 STM32 CPU 执行这段程序，从而完成 Flash 编程。

``` plain_text
OpenOCD:
    "擦除 Sector 0"
          │
          ▼
OpenOCD Flash Driver:
    "设置相应控制寄存器"
          │
          ▼
PWLINK:
    "通过 SWD 完成寄存器写访问"
          │
          ▼
STM32 Flash Controller:
    "检测到有效的擦除启动条件"
          │
          ▼
内部硬件状态机:
    "执行擦除时序"
          │
          ▼
Flash Array:
    "存储单元进入擦除状态"
```

# makefile

=  : 递归赋值变量
:= : 立即赋值变量

how to refer to the variable? use $(variable)

and $$ will transfer the real $ to the shell(let the shell to expand the shell-variable, like `$$HOME`)

Normally, make will consider the target as a file. If define a target named `flash`, and (unfortunately) if there's a file named `flash` in the current directory, then make will check the info of flash and find nothing in the prerequisites is modified later than flash, then `make` will think there's no need to execute the recipe again, which is not we want, and that's where `.PHONY` comes.

`.PHONY` is a special target in makefile. It tells make that `flash` doesn't represent a real filename, just execute it.

`@` : when a command starts with `@`, make will only print the command output, not the command itself(default behaviour)

| 自动变量 | 含义                 |
|----------|----------------------|
| `$@`     | 当前规则的目标名称   |
| `$<`     | 第一个依赖文件       |
| `$^`     | 所有依赖文件（去重） |
| `$?`     | 比目标更新的依赖文件 |
