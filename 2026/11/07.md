# freertos

`configTICK_RATE_HZ`  configs the hz of time slice. At the end of a time slice, scheduler will select a new task to run.

However, it is not the only way. Scheduler will also select a new task to run immediately after the currently executing task enters the **Blocked** state, or when an interrupt moves a higher priority task into the **Ready** state

## block state

event-driven tasts

tasks can enter the blocked state to wait for two different types of events

1. temporal events
2. synchronization events

## suspended state

suspended state is also a sub-state of not running state. 

the only way to enter the suspended state is through a call to the vTaskSuspend api function

and the only way out is through a call to the `vTaskResume` or `xTaskResumeFromISR` (isr : interrupt servie routine) api functions. Most applications do not use the Suspended state.

## ready state

tasks in ready state are ready, they are not blocked or suspended. They can run, but are not currently running.

There are several other disadvantages to any from of polling, not least of which is its efficiency.

# cpu 占用率

cpu占用率是如何计算的？

统计在一个周期之内， 非空闲时间的比例（包括用户态代码， 内核态代码， 已经部分中断处理时间）

cpu占用率并不等同于计算能力利用率， 如果想分析计算效率， 就需要引入一些额外的指标：

- IPC（Instructions Per Cycle）：每个时钟周期完成的指令数。
- Cache miss rate（缓存未命中率）。
- Memory bandwidth（内存带宽）。
- CPU frequency（CPU 频率）。

在linux上， 可以使用`perf stat ./program`

some useful tools:

| 工具                   | 分析内容                                  |
|------------------------|-------------------------------------------|
| `htop`                 | 整体 CPU 和进程情况                       |
| `mpstat`               | 每个逻辑 CPU 的使用率                     |

| `perf stat`            | CPU cycles、instructions、cache misses 等 |
| `perf record`          | 找到程序的性能热点                        |
| `trace-cmd` / `ftrace` | 分析内核调度事件与延迟                    |

# c

1UL(unsigned long)
`ICSR = (1UL << 28);` 这里不会吧其他位置为0, 原因是硬件寄存器可以有特殊的写入语意， 这里其他字段都是只读位， 并且如果写成|=反而会让一次写操作编程三次操作：读， 修改， 写。

gcc允许我们直接嵌入汇编代码， 例如：`__asm volatile("nop");`

``` c
__asm volatile (
    "assembly instructions"
    : output_operands
    : input_operands
    : clobbers
);
```
| 部分          | 意义                                 |
|---------------|--------------------------------------|
| 第一个 `:` 后 | 输出操作数                           |
| 第二个 `:` 后 | 输入操作数                           |
| 第三个 `:` 后 | 被修改的寄存器或其他状态（clobbers） |

例如：

``` c
int a = 10;
int b;

__asm volatile (
    "mov %1, %0"
    : "=r"(b)
    : "r"(a)
);
```

## 指令集 Instruction Set

值得就是指令的集合: add, sub, load, store, mov, cmp, jmp, and ...

## 指令集架构 Instruction Set Architecture

更加完整的规范， 包括指令及其语义， 程序员可见的寄存器， 机器指令的编码， 内存访问及执行行为， 异常和特权机制

## 微架构 Microarchitecture

决定cpu内部怎么执行指令， 例如cpu有几级流水线， 加法器如何设计， cpu是否乱序执行

Arm是公司， 它指定Arm ISA规范， 同时还设计cpu核心

ARMv7E-M是架构规范(ISA)

Cortex-M4是cpu核心设计， 有自己的微架构设计

Cortex是Arm设计的一系列cpu核心产品的品牌名称

| 名称                  | 含义                                   |
|-----------------------|----------------------------------------|
| ARM（宽泛用法）       | 整个 Arm 架构家族                      |
| ARM（历史指令集用法） | 传统 ARM 指令集                        |
| Thumb                 | 一种历史上以紧凑编码为目标的指令体系   |
| Thumb-2               | 扩展 Thumb，结合 16 位和 32 位指令编码 |
| AArch32               | Arm 的 32 位执行状态                   |
| AArch64               | Arm 的 64 位执行状态                   |
| A32                   | 传统 ARM 指令集的现代称呼              |
| T32                   | Thumb 指令体系的现代称呼               |
| A64                   | AArch64 使用的指令集                   |
